# Project Rules

## Цель

Создать работающий MVP «Архив Терпения».

Главный критерий:
работоспособность > архитектурная сложность.

## Рабочий цикл

Для каждой задачи:

1. Прочитать существующий код.
2. Определить минимальное изменение.
3. Реализовать.
4. Проверить.
5. Исправить.
6. Повторно проверить.
7. Зафиксировать результат.

## Не делать

Не создавать абстракции без текущего потребителя.

Не создавать framework ради framework.

Не создавать multi-agent architecture до доказанной необходимости.

## При сомнении

Выбирать более простой вариант.

Если два решения одинаково работоспособны,
выбирать то, которое:

- имеет меньше зависимостей;
- проще тестируется;
- проще объясняется;
- проще удалить;
- проще заменить.
