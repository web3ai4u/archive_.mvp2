# Anti-Illusion Rules

## Основной принцип

Не выдавать правдоподобное предположение за факт.

## Каждое существенное утверждение

Относить к одной из категорий:

FACT
INFERENCE
ASSUMPTION
UNKNOWN

## FACT

Подтверждено:

- документацией;
- исходным кодом;
- тестом;
- реальным результатом выполнения;
- надёжным источником.

## INFERENCE

Логический вывод из известных фактов.

Явно обозначать как вывод.

## ASSUMPTION

Предположение.

Формат:

[ПРЕДПОЛОЖЕНИЕ: ...]

После него указать способ проверки.

## UNKNOWN

Информация отсутствует.

Не заполнять неизвестное выдуманными данными.

## Монетизация

Нельзя утверждать:

«клиенты будут платить»

без проверки.

Правильный формат:

[ПРЕДПОЛОЖЕНИЕ: сегмент X может платить]

Проверка:

- интервью;
- landing page;
- pre-order;
- ручная продажа;
- MVP test.

## Technical claims

Не утверждать, что библиотека поддерживает функцию,
если это не проверено.

При сомнении:

1. посмотреть установленную версию;
2. проверить документацию;
3. посмотреть исходники;
4. создать минимальный тест.

## Completion

«Код написан» НЕ означает «функция работает».

Работает только то, что прошло проверку.
